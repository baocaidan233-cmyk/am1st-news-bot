# AM1ST（America First）新闻频道 — 运行规则文档

最后更新：2026-08-06

## 一句话说明

这是从原来的 n8n 自动化workflow迁移过来的 Python 版本。整个系统分成两个**完全独立、互不等待**的流程：一个负责抓新闻、筛选、生成文案、存起来；另一个每隔一段时间从存好的那批里挑一篇发出去。两个流程各自有自己的调度节奏，中间靠一个共享的 Notion 数据库（候选池）传递信息。

```
┌─────────────┐        写入候选池        ┌─────────────┐
│  抓取流程     │ ──────────────────────▶ │  候选池      │
│ main.py     │                          │ (Notion库)   │
│ 每10分钟一次  │                          └──────┬──────┘
└─────────────┘                                  │ 读取
                                                  ▼
                                          ┌─────────────┐
                                          │  发布流程     │
                                          │main_publish.py│
                                          │ 每30分钟一次  │
                                          └─────────────┘
```

---

## 一、抓取流程（`main.py`）

**调度**：每 10 分钟一轮（`poll_interval_seconds`），实际间隔会加 ±10% 随机抖动，避免和别的机器人同时打 API。

**每一轮按顺序做这些事，前面的步骤把稿子淘汰掉，后面就不用再处理，省钱省时间：**

1. **读信源列表**（Notion "rss_n8n_am1st_news" 库）——只处理 `in_use` 勾选为true 的行，里面记录着每个网站的 RSS 地址、付费墙 cookie（如果有）。

2. **抓 RSS**——用 feedparser 解析，时间统一转成 UTC。只留发布时间在最近 **3 小时**以内的（`max_publish_age_hours`）。如果某条的发布时间解析不出来，默认放行（宁可多留、不错杀）。

3. **去重第一层 —— Redis 精确查重**：对每条新闻的链接算哈希值，查 Redis 里有没有见过。见过就跳过，没见过就记下来，**保留 10 天**（`redis.ttl_seconds`）。这是最便宜的一层，先过滤掉明显重复的。

4. **同一轮内语义聚簇**（2026-08-06 从"简单去重"改成真正的本地聚簇）：把标题+摘要转成向量，跟这一轮已经处理过的稿子两两比较：
   - 相似度 **≥ 0.8**（`dedup.semantic_threshold`）：判定是本轮内的近乎重复，不单独成候选，但**把这条的信源记入它匹配到的那个簇**——这是 2026-08-06 补的一个漏洞：以前这种直接丢弃、完全不计入热度。
   - 相似度在 **0.6～0.8** 之间（`heat.related_threshold` 到 `dedup.semantic_threshold`）：算同一个簇里不同角度的报道，自己单独成候选，但跟簇里其他成员共享同一份热度信息。
   - 相似度 **< 0.6**：自成一个新簇。
   
   一轮下来，本批抓到的稿子被分成若干个"簇"，每个簇附带一份"目前涉及哪些信源"的名单（包括被当重复丢弃、不会单独成候选的那些）。

5. **跨轮次查重（逐条）+ 事件热度预览（按簇，只读）**：
   - **跨轮次查重**（Qdrant 库 `am1st_embeddings`，过去 **72 小时**内，`qdrant.cross_cycle_window_hours`）：还是逐条比较，跟以前逻辑一样，判断这篇是不是跟历史上某篇文章几乎一样，≥0.8 就丢弃——这一步没有按簇合并，因为"这条稿子是不是历史上某篇的重复"跟簇内其他成员未必一致，要保持逐条判断的精度。
   - **事件热度预览**（`am1st_events`，2026-08-06新加的单独Qdrant库，**只读，不写**）：每个簇只查一次（不是每条候选查一次）——拿簇里第一个成员的向量，去`am1st_events`里找有没有匹配到**已经存在的**历史事件（相似度≥0.6，且10天内还在更新的，`heat.window_hours`=240小时，跟Redis的10天惯例一致）。查到的话，把历史事件的热度数字，加上本簇这一轮新发现的信源，拼成一个"预览热度"；查不到就当全新事件，预览热度按本簇内部信源数算。**这一步只是问一下，不往库里写任何东西**——避免不相关内容（体育、娱乐）白白污染事件库，见下面第7点。

6. **AI 打分**（gpt-4o-mini）：给标题+摘要（外加上一步算出来的"预览热度"）打分，**低于 5 分**（`openai.score_threshold`）的直接淘汰，不进入下一步（省下全文抓取和生成文案的成本）。

7. **全文提取**：用 httpx 抓网页正文 + trafilatura 解析。如果这个源配置了付费墙 cookie，会带上 cookie 一起请求。抓到的正文低于 **200 字**（`extraction.min_text_length`）算提取失败——按失败处理，同时会往 Notion 源库对应行的评论区 @你 提醒（有 6 小时冷却，`alert_cooldown_seconds`，不会同一个源一直刷屏提醒）。**目前 NYT/FT/Economist/Bloomberg/华盛顿邮报这几个付费墙网站还抓不到正文**（需要 Playwright，还没接）。

8. **生成发布文案**（gpt-4o-mini）：基于全文生成一段适合发到 Gettr 的文案。如果模型判断这条新闻不值得发（返回 "No comment"），直接过滤掉，不进候选池。

9. **按簇决定要不要真的写进事件库,然后写入候选池**：**只要这个簇里有任何一条打分≥5分**,才会：把这个簇累积的信源信息真正提交到`am1st_events`(这时候才实际写库),更新/新建事件的`heat_score`/`first_seen_at`；**如果整个簇没有一条过5分(比如体育、娱乐新闻),事件库从头到尾都不会被碰**——不需要额外判断"是不是时政"，复用打分这道现成的关卡就够了。提交完之后，把打分≥5分的每条候选（标题、链接、作者、摘要、发布时间、正文、AI打分、AI评语、生成的文案、链接哈希、最终确定的`heat_score`、`event_first_seen_at`）写进 Notion 候选池（测试环境是 `am1st_news_log` 这张表复用来测试），`send_status` 留空（false）。同时把每条候选的标题+摘要向量写入 Qdrant `am1st_embeddings`（供步骤5未来跨轮次查重用）。

**这一步结束——抓取流程不会自己发布任何东西，纯粹是"攒稿子"。**

## 二、发布流程（`main_publish.py`）

**调度**：每 30 分钟一轮（`publish.interval_seconds`），同样带 ±10% 抖动。

**每一轮按顺序做：**

1. **查候选池**：条件是 `send_status ≠ true`（还没发过）、创建时间在 **12 小时以内**（`publish.candidate_max_age_hours`）、AI 打分 **≥ 6 分**（`publish.candidate_min_score`），按打分从高到低排序。

2. **过滤过期措辞**：关键词过滤掉那种明显过时的"前总统特朗普"式表述（这是直接照抄原来 n8n 里那条规则）。

3. **分层挑选一批（尽量凑够10篇，最少3篇）**：
   - 判断今天是不是工作日（美东时区）：工作日新闻多，优先门槛用 `publish.weekday_min_score`=6 分；周末新闻少，直接用 `publish.weekend_min_score`=5 分门槛
   - 优先挑 **4 小时内**（`publish.fresh_hours`）且打分 **≥ 7** 的
   - **没凑够10篇就继续放宽**到4小时内、达到上面门槛的也算
   - 还没凑够10篇就不管时效性，只要打分达到门槛的都算
   - 工作日专属：还没凑够10篇，放宽到周末的 5 分门槛
   - 只有当**一条真正打了分的候选都没有**时，才触发最后兜底：不管分数，直接拿最新的几篇（凑够3篇就停，不会为了凑数硬拉没打分依据的稿子）
   - **2026-08-06 改的**：以前是凑够3篇（`batch_min`）就直接停，不会往下继续放宽门槛——导致某条新闻按平时主题权重只能打6分，但当天恰好是热点，只要同一时间段已经有3篇以上7分稿子，这条热点稿连进入候选批次的资格都没有,第4步AI重排再怎么强调"热度高该顶格"也救不回来。现在改成**只要没打过分的候选门槛还没占满10个坑,就继续往下一层放宽**,让更多真实打过分的候选进入AI重排这一步,由重排来判断哪条更值得发,而不是在这一步就替它挡在外面。

4. **AI 重新排优先级**（gpt-4o-mini，第二次打分，这次是基于生成好的文案内容，不是标题摘要）：给这一批稿子重新打一个 1-10 的"优先级分"，重点是"现在这个时间点，哪篇最值得发"。同时会看 Google News 当前的美国政治热点标题（只读，一个免费、不用 API key 的信号，抓的是 NATION 板块），以及每篇稿子的两个新鲜度数字——`hours_old`(这件事整体存在了多久,来自`event_first_seen_at`)和`hours_since_update`(这篇具体报道自己发布了多久,2026-08-06新加)。这两个数字故意分开送,不合并成一个:一个持续几天的案子如果今天有新进展(新证据/新人物),这篇报道按`hours_since_update`是全新的,不该因为`hours_old`大就被当成旧闻打低分——只有当两个数字都大、且没有主流媒体热度支撑时,才真按旧闻处理。**另外单独强调一条(2026-08-06新加)：如果`heat_score`异常高(几乎所有主流媒体当天都在同时报道)，这本身就是"今天全国头条"的强证据，即使这个话题按平时的主题权重不算突出，也该给最高档优先级——不需要再靠别的信号佐证，全网同时报道这件事本身就是信号**（例子：某个话题平时权重一般，但当天有个大新闻发生，那天就该顶格优先）。按最终分数从高到低排序。

5. **已发布查重**（Qdrant 向量库，collection `am1st_posting_news_embedding`，专门存"已经真正发出去的文案"，跟抓取阶段的向量库是两个完全不同的库）：把生成的文案转成向量，跟**过去 24 小时**（`publish.posted_dedup_window_hours`）内实际发布过的比较，**余弦相似度 > 0.70**（`publish.posted_dedup_threshold`）就算重复。**这个阈值比抓取阶段的 0.8 更严格**——因为这是机器全自动发布，宁可少发也不要发出明显重复的内容。**2026-08-06 修了一个真bug**：之前比对用的是"文案+末尾附的链接"整段文本一起转向量，链接本身是跟内容无关的字符串,会稀释相似度——真实抓到一个案例(The Federalist和Daily Caller两个信源报道同一件2020年Maricopa County选民数据泄露案),纯文案比对相似度0.731(该拦),带着链接一起比掉到0.698(漏判,两条都发出去了)。现在改成只用**纯文案**(去掉链接那部分)做向量比对,链接还是照样会附在真正发出去的帖子里,不影响发布内容本身。

6. **按优先级顺序，从高到低找第一个不重复的**：遇到重复的就跳过（只打日志，不再单独记录到 Notion——8/5 决定简化掉了"记录跳过稿件"这个环节，之前设计是要记一笔日志，后来讨论后觉得没必要）。找到第一个不重复的就是这一轮的赢家。如果这批全都是重复的，这一轮就**不发**，不会硬凑一篇发出去。

7. **发布到 Gettr**（2026-08-05 接通，`agents/gettr_publisher.py`）：真的调用盖特发帖接口，用测试账号。**2026-08-06 加了链接预览卡片**——之前发出去的帖子，链接只是纯文字、没有预览图/标题/摘要（你截图发现的问题）。原因是盖特的发帖接口需要单独传`dsc`/`previmg`/`prevsrc`/`ttl`这四个字段才会显示预览卡片，之前代码没传。现在发布前会先抓一次原文链接的OG元数据（`agents/og_metadata.py`，先试盖特自己的`caps.gettr.com`抓取代理——绕过很多新闻网站的反爬——抓不到再直接请求原网站），拿到标题/摘要/图片后一起传给发帖接口。已经发一条真实测试帖验证过（`p42ijus2c2e`），盖特那边确认存了这四个字段。

8. **标记已发**：只有真的发布成功才会：把候选池那一行的 `send_status` 改成 true，并把这条文案的向量写进"已发布"库供下次查重用。发布失败不会误标记、不会污染查重数据。

## 三、涉及的外部服务

| 服务 | 用途 | 备注 |
|---|---|---|
| Notion（源库） | 存 RSS 信源列表 | 用 `NOTION_API_KEY` 这个 key |
| Notion（候选池库） | 抓取流程写、发布流程读 | 用 `NOTION_CANDIDATE_API_KEY` 这个独立的 key，跟源库的integration 不是同一个 |
| Redis（Upstash） | 抓取阶段第一层去重（URL 哈希） | 10 天过期 |
| Qdrant | 三个独立 collection：`am1st_embeddings`（抓取侧跨轮次查重）+ `am1st_posting_news_embedding`（发布侧"已发布"查重）+ `am1st_events`（事件聚合/热度，2026-08-06新加） | 复用团队现有的共享集群，多个频道共用同一个集群、各自不同 collection |
| OpenAI（gpt-4o-mini） | 打分 ×2 次（抓取时、发布时）+ 生成文案 + embedding | |
| Gettr | 实际发帖 | 已接通（2026-08-05），用测试账号验证过真实发布成功；2026-08-06 加了链接预览卡片 |
| Gettr（`caps.gettr.com`） | 抓取原文链接的OG元数据（标题/摘要/图），供预览卡片用 | 2026-08-06新加，盖特自己的抓取代理，抓不到再直接请求原网站 |
